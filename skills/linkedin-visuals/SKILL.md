# Carousels and post visuals

Use the shared scope and factual rules in the [master skill](../../SKILL.md).
This module can be read directly but requires the repository references.

## Inputs

Post/message, intended visual format, brand inputs and requested output files.

## Workflow

1. Decide what the visual explains: sequence, comparison, mechanism, evidence or a key statement. Use one image for one simple idea; use slides when a sequence adds value.
2. Draft an informative cover, one idea per slide, legible content and a useful recap. Fit slide count to the content instead of padding to a template quota.
3. For quote cards, use deterministic typesetting where appropriate; preserve exact text, attribution and readable contrast. For generated illustrations, follow the available image-generation skill and tool.
4. For PDF or PowerPoint delivery, use the corresponding artifact skill and render/inspect the output. If rendering tooling is unavailable, deliver an explicit layout/copy specification and say that an actual file has not been rendered.
5. Follow existing project renderer and regeneration boundaries when working on an app. Do not change backends, upload brand assets or assume paid credits merely because an upstream example does so.
6. Deliver actual local files when generated, with caption and source/alt-text notes as appropriate. Producing a visual does not publish it.

## Deliverable

Visual specification or verified rendered artifact(s), supporting post copy and attribution/accessibility notes.
