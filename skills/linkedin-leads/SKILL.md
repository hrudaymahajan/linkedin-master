# Lead research and qualification

Use the shared scope and factual rules in the [master skill](../../SKILL.md).
This module can be read directly but requires the repository references.

## Inputs

User-owned ideal customer criteria, candidate source and requested scope.

## Workflow

1. Reuse the user's stated criteria or obtain the missing target roles, company characteristics, location and exclusions. Do not import a source repository's sample customer profile.
2. Define a bounded candidate set. Use supplied records or an authorized reading source and retain source identifiers and dates.
3. Deduplicate by verified identity; a public profile URL and Sales Navigator hashed URL may refer to one person. Preserve unresolved identity ambiguity.
4. Assess each candidate against explicit criteria; record suitable, unsuitable or insufficient evidence, with the decisive evidence and reason. Unknown company size is not a guessed match.
5. Deliver a traceable lead list and optionally draft relevant outreach. Qualification does not imply consent, buying intent or permission to send.
6. For an explicitly requested pipeline implementation, separate import batches, candidates, qualification, ownership, operation logs and connection state. Use resumable transitions and reconcile unknown external outcomes before retrying.
7. Recurring invitations, withdrawals and cross-account retries described upstream are not activated by this skill. They require a separate compatible implementation request and authorization; do not rotate accounts to evade restrictions or continue unwanted contact.

## Deliverable

Qualified records with reasons, source and unknowns; requested draft outreach or a pipeline design with state and dependency boundaries.
