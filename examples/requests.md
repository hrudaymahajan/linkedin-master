# Example requests and expected behavior

These are usage scenarios, not reports of executed account actions.

## Source-backed post

Request: “Use this release note to explain the change to junior developers.”
Route: research → writing → quality.
Deliver: an accurate standalone draft, practical implications and source notes.
Preserve uncertainty. Do not invent a personal test, quote or benchmark.

## Repurpose a long source

Request: “Make three different posts from this transcript.”
Route: writing → quality.
Deliver: three distinct, finished posts when the source supports them. Keep quoted
speakers and claims attributed; do not substitute the user's identity for theirs.

## Mixed comment thread

Request: “Draft responses to these questions, praise and a sales pitch.”
Route: comments → quality.
Deliver: target-labelled responses to substantive messages, counts and reasons for
skipped noise. No sending, reacting, inbox deletion or account access is implied.

## Incomplete profile

Request: “Score my profile. Here are my headline and About.”
Route: profile → quality.
Deliver: evaluate those sections and mark everything else unassessed. Provide
useful rewrites without inventing work history or a complete-profile score.

## Sparse analytics

Request: “Which of these four posts worked best? One has no impressions listed.”
Route: analytics → strategy.
Deliver: compare observed metrics, leave the missing rate unavailable and avoid
causal claims or a supposedly optimal posting time from four observations.

## Full carousel package

Request: “Create a PDF carousel explaining this process and a caption.”
Route: writing → visuals → quality.
Deliver: the requested rendered and inspected file when artifact tools are available,
plus caption and sources. A slide outline alone is not a completed PDF.

## Publishing without a connected backend

Request: “Publish this approved post.”
Route: publishing.
Deliver: identify the missing backend, finish the concrete manual package and state
that it is not published. Do not install an unrelated service or invent a receipt.

## Existing manual-only application

Request: “Use the master skill to improve our local content generator.”
Route: relevant content modules, after reading project instructions.
Deliver: authorized local changes respecting project history and regeneration rules.
The combined skill does not override project scope or activate account automation.
